# 01. 决策、不变量与实现澄清

> 所有数值为 V1 建议起点，须通过 G0 和实测冻结。不是当前项目已有行为或已完成的安全认证。

## 1. 需要在开工评审冻结的决策

| 决策 ID | V1 建议 | 变更触发与责任人 |
|---|---|---|
| DEC-01 | 一家企业为 Org；部门/项目/个人为内部授权范围 | 多法人/外部客户需要 ARCH/SEC 重审隔离域 |
| DEC-02 | FastAPI 模块化控制服务 + 独立 Worker + 可信 manager | 不因图上有多个框就强行拆微服务；ARCH |
| DEC-03 | PG 为权威事实；Redis 只加速 | 新队列需写清事务/幂等迁移；BE/PE |
| DEC-04 | READ COMMITTED + 显式行锁/唯一约束；仅纯 DB 事务有限重试 | 更换隔离级别须重测冲突与快照；BE-A |
| DEC-05 | 同 Session 一个未解决 Run；同项目一个写发布者 | 协作/并行写必须新增合并与副作用策略；PM/BE |
| DEC-06 | 惰性按 Run 分配隔离执行；可有 compute/connector/parser 多 cell | 具有不同权限的进程不得因同 Run 就共用 Secret；PE/SEC |
| DEC-07 | 模板、Skill、模型配置、镜像内容不可变，启停/Grant 独立可变 | 回滚不修改旧内容或篡改历史；BE |
| DEC-08 | 持久审批针对 ActionSpec；派发后不明效果需核对 | 下游无幂等/查询的高风险写保持关闭；业务/SEC |
| DEC-09 | RLS 作为防误用层，应用仍全链路授权 | 更强租户边界需独立角色/数据域方案；SEC/DBA |
| DEC-10 | 文档/产物来源保守传播，分享不能降低源限制 | 脱敏/解密/解限需有批准流程；业务/SEC |
| DEC-11 | API key/模型端点由受控版本选择；生产禁配置 Shell | 个人 Key 也经 SecretRef 与端点准入；BE/SEC |
| DEC-12 | 所有恢复、费用、输出限制有明确的失败状态和责任人 | 不以 unknown=0 或失败后静默重跑提升成功率；BE/PE |
| DEC-13 | 抽取一个标准计算 profile 先走通，其余能力按 profile 单独验收 | 不以 Python 通过代替 browser/stdio/parser；QA/SEC |
| DEC-14 | Codex 等新引擎不进入 V1 必经路径，固定版本独立评估 | 未满足官方支持/授权/安全要求只能实验；ARCH |
| DEC-15 | 对普通业务用户隐藏基础设施复杂性，但不隐藏失败与费用不确定性 | UX 调整不得取消安全边界；PM/FE |

每项记录：状态 proposed/approved/rejected、批准人、日期、依据、适用用户/数据范围、关联任务/测试、复审条件。不以“默认推荐”冒充企业已批准。

## 2. 30 条不可被模块自行绕过的不变量

| ID | 强制约束 | 典型反例 | 主要任务 |
|---|---|---|---|
| INV-01 | 用户身份只来自验证过的登录/服务主体 | body.user_id 被当真实调用者 | IAM-01/02/04 |
| INV-02 | 每次资源访问同时满足 Org、动作、资源和当前主体授权 | 知道 UUID 就能下载 | IAM-05/06 |
| INV-03 | 租户 FK、查询/事务上下文一致，连接回池不残留身份 | A 的连接被 B 复用仍带 org A | DAT-02/06 |
| INV-04 | 权限清单是调用上限，当前撤权/禁用仍要生效 | 旧 Manifest 永久授权 | IAM-08/CAP-02 |
| INV-05 | Secret 不进入用户代码通用环境、业务日志或普通响应 | 全公司 Key 放入共享 .env | IAM-07/SBX-12 |
| INV-06 | 不可信代码/文件解析/stdio 进程不在控制服务执行 | 管理员测试按钮直接 subprocess | CAP-07/SBX-04 |
| INV-07 | 控制/管理事实由可信边界核对，非由沙箱自报 | 代码打印 destroyed:true 即释放资源 | SBX-02/11 |
| INV-08 | 跨用户及不同权限 cell 的文件/进程/Secret/网络隔离 | 同 Run 的计算脚本读连接器管理员 Token | SBX-05/12/MCP-05 |
| INV-09 | 总 CPU/内存/PID/磁盘/inode/时间/输出都受真实限制 | named volume 无限写，仅每晚清理 | SBX-07 |
| INV-10 | 网络默认拒绝，批准出口不包含管理面/其他用户 cell | internal 网络中的 Harness 可被代码任意访问 | SBX-08 |
| INV-11 | Run/Job/输入消息/初始事件/预算一起可靠创建 | 返回 run_id 但队列或预算没提交 | RUN-02/10 |
| INV-12 | 相同幂等业务动作重复提交不会产生第二份效果 | HTTP 超时后当新任务再次写入 | RUN-02/MCP-06 |
| INV-13 | 旧 generation 不能执行新命令、发布、提交新业务事件 | 旧 Worker 恢复后覆盖新工作区 | RUN-03/SBX-09 |
| INV-14 | 未决/未知副作用有显式阻断与核对，不能伪装已失败 | outcome_unknown 被直接入重试队列 | RUN-09 |
| INV-15 | 审批绑定不可变参数、输入、代码、身份与有效期 | 批准后更改脚本再执行 | RUN-08/CAP-05 |
| INV-16 | 数据库事务不跨模型/HTTP/容器/用户等待 | 一边持行锁一边等 5 分钟审批 | DAT-06/RUN-08 |
| INV-17 | 事件持久化、顺序和重复语义可恢复 | SSE 随机推送但重连丢终态 | RUN-04/05 |
| INV-18 | 成功必须有可靠结果/产物/用量状态，清理单独核对 | 文本生成完但上传失败仍显示成功 | RUN-07/SBX-10 |
| INV-19 | 输入/工作副本固定版本，发布校验期望 head 和写租约 | 两个 Run 直接编辑同一共享目录 | SBX-09 |
| INV-20 | 用户内容不能通过包/路径/压缩/预览获得额外执行能力 | zip slip 或同域 HTML 窃取会话 | CAP-03/UI-05 |
| INV-21 | 工具/模板/代码版本固定，依赖关系和权限可审计 | 发布新 Skill 悄悄改变活跃任务脚本 | CAP-04/05/06 |
| INV-22 | MCP 外部身份与连接池按实际权限主体分区 | 同 endpoint 共享 Bearer/Cookie | MCP-02/03 |
| INV-23 | 文档 ACL 在召回/重排/入模前生效，引用再检查 | 先给模型全文再删未授权引用 | KB-05/06 |
| INV-24 | 删除/撤权和来源限制传播到派生数据、缓存、恢复 | 受限文档生成报告后自动公开 | KB-07/GOV-06 |
| INV-25 | 预算并发可预留、费用可核对，unknown 不作免费 | 流断开就丢掉已花费用 | RUN-10/GOV-03 |
| INV-26 | 高风险副作用之前有可靠授权/审批/意图审计 | 先执行，稍后日志失败当没发生 | GOV-02/MCP-06 |
| INV-27 | 支持访问限时限字段、访问本身有审计 | 运维能默认打开全部聊天与 Cookie | IAM-09/GOV-05 |
| INV-28 | production 依赖或策略不满足时拒绝，不降级到共享宿主 | manager 故障就本机运行 Python | FND-05/OPS-02 |
| INV-29 | 备份/灰度/回滚不丢新事实、不复活已撤权内容 | 恢复旧 DB 抹掉新账本/离职状态 | OPS-03/REL-05 |
| INV-30 | 每项放行有固定版本/环境/范围证据，未测不声明安全 | 仅规划文档完成就把任务标上线 | REL-02/06 |

这些不变量是实现断言和验收导向，不是现实系统已经具备的保证。外部不可撤回效果、基础设施 root 权限、未知内核漏洞等边界必须明示。

## 3. 本轮对已有计划的明确修订

| 澄清 ID | 原计划可能被误解的地方 | 具体修订 |
|---|---|---|
| CLR-01 | 一个 Run 必须只有一个容器 | 同权限计算可复用 compute cell；有凭据 connector/parser/broker 可独立 cell，通过 target_slot 明确绑定 |
| CLR-02 | 同 Run 中 stdio MCP 的凭据可给所有代码看 | 默认 credentialed connector 与任意代码分离；没有分离就不能声称工具级审批能限制直接凭据使用 |
| CLR-03 | app.org_id 的 RLS 可抵御任意 SQL/数据库密码泄漏 | GUC 来自可信应用，只防错误查询/上下文遗漏；SQL 注入/凭据失陷需要另外防御与事件响应 |
| CLR-04 | stdout 分流后所有 runner 结果都可信 | 同 UID 代码仍可能影响进程；信任只止于外部 manager 确认的进程/资源事实，用户输出永远是数据 |
| CLR-05 | 权限撤销“立即”意味着收回所有网络字节 | 定义授权决定/派发的可测边界，阻止新的获权决定；在途/已披露内容只能记录影响 |
| CLR-06 | waiting_approval 环境丢失可直接普通失败/重跑 | 允许进入 recovery_required；权限审批事实保留但执行许可失效 |
| CLR-07 | 未知效果任务释放所有占用就可继续 | 释放计算资源，但保留 Session 未解决槽及必要业务资源 blocker，核对后显式解除 |
| CLR-08 | 审批只需对 arguments 做 JSON hash | 还覆盖规范化版本、脚本/输入/依赖/外部目标/凭据 scope；generation 是派发授权而非商业幂等键 |
| CLR-09 | 同时为 Run/Manifest 建非空双向 FK 随便插入即可 | 预分配 ID、仅必要 FK 延迟检查或单向归属设计；TX-01 规定顺序，提交前全部存在 |
| CLR-10 | 制定 status CAS 就解决了所有并发 | 声明全局锁顺序、禁止外部 IO 期间持锁、数据库有限重试；对外效果不在事务内自动重试 |

## 4. 安全控制的失效域

| 控制 | 可以约束 | 不能单独约束 |
|---|---|---|
| PolicyService | 已验证身份对 API/资源/工具的授权 | 拿到 root/DB 密码的攻击者 |
| RLS + trusted context | 常见遗漏 WHERE、连接上下文错误、跨组织 FK | 同 DB 角色任意设置上下文后的恶意 SQL |
| OCI/增强隔离/微 VM | 对应配置/内核下的文件进程资源网络边界 | 未知漏洞或被授予外部账号的业务权限 |
| ActionSpec/审批 | 一次被描述且未被更改的动作 | 可直接使用同 Secret 的任意代码或不可查询的远端结果 |
| Content digest/签名 | 指向某份内容、来源和构建版本 | 内容本身无漏洞、运行期一定不恶意 |
| 输出清洗/提示规则 | 降低注入和 UI 执行风险 | 完全消除模型被欺骗的可能 |
| 审计/监控 | 事后定位、控制失效告警、动作前事实保障 | 自动撤销已发生的外部影响 |

## 5. 规格数值与测量口径

初始建议：job 心跳 10 s/lease 45 s；审批最多 5 min 且不得越过 Run deadline；SSE 聚合 100–250 ms；queue TTL 15 min；普通分析 Run 10 min。每个值只在相同的测试 profile 中验收，定期调整要记录版本。

- 时间使用 UTC wall clock 存储、权威 DB/服务时间判断租约，单调时钟计量本进程耗时。
- 期限取 `min(Run 剩余, 工具上限, 凭据/审批有效期, 企业业务上限)`；未知剩余时失败，不推成无限大。
- PID/CPU/内存/磁盘硬限制与准入是不同控制，二者都验证。
- SLA、RPO/RTO 只有演练和故障域支持才可对外承诺，文档里的建议值不是性能报告。

## 6. 变更审查模板

任何新增工具、schema、profile、模型或权限行为的 PR 回答：影响哪些 INV？谁是可信输入？哪些已有数据需要迁移？故障点在哪里？重试会否重复副作用？撤权如何生效？如何关闭而不丢事实？哪条 ECASE/原测试证明？

若回答仍是“框架应该会处理”“用户不会这样用”“我们部署内网”，该项不能通过安全设计评审。
