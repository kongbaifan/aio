# 02. 产品范围、用户流程与可验收需求

> 本文件是实施用 PRD 草案。默认值是工作假设，G0 由产品、业务、安全共同确认。P0/P1 表示发布优先级，不表示已经实现。

## 1. 产品边界

### 1.1 要解决的问题

- 员工打开统一网页，选择预配置 Agent，提交任务、文件或问题，得到可理解、可下载、可追踪的结果。
- 平台统一维护共享 Skill、MCP、知识库，允许有权限的部门维护自己的能力。
- 员工可以建立个人连接或提交自定义能力，但不能因此获得服务器命令执行权、内网通行权或其他用户凭据。
- 对执行环境实行可回收隔离，避免包安装、恶意/错误代码、资源耗尽影响控制平台和其他用户。
- 管理员能够在不默认窥视业务内容的前提下排障，审计能回答谁、何时、为什么、用什么身份、访问了什么资源。

### 1.2 不作为首版承诺

- 不承诺所有任务都能完成、任意脚本都能安全运行、任意第三方 MCP 都能直接接入。
- 不提供所有用户都拥有 root 的共享远程桌面。
- 不默认允许任意系统包安装、任意出网、任意内网访问、任意模型 endpoint。
- 不自动把所有聊天内容写入跨用户长期记忆。
- 不承诺跨机器保存任意 Python/JS 内存状态；持久文件与可恢复对话不等于持久进程。
- 不承诺外部系统的写操作可以自动撤销或 exactly-once。
- 不将完整流程设计器、多智能体自治协作市场、实时协作文档纳入安全试点关键路径。

## 2. 业务对象与术语

| 对象 | 定义 | 注意事项 |
|---|---|---|
| Organization / Org | 一个企业租户或法律/安全组织边界 | 首版可能只有一个，也必须进入资源键和授权上下文 |
| Department | Org 内的部门或身份组 | 用户可以加入多个部门；不能通过部门 ID 猜测权限 |
| Project | 一组工作数据、产物和成员权限 | 可为个人或团队；新用户可自动创建私有默认项目 |
| AgentTemplate / Version | 模型、指令、允许能力、默认策略的发布模板 | 员工使用固定版本，发布者不能越过组织策略上限 |
| Session | 用户与某 Agent 在项目内的一段对话 | 同一用户多个 Session；默认私有，即使项目文件可共享 |
| Run | 一次用户任务的实际执行记录 | 可以包含多轮模型、多次工具调用、多步骤 team |
| Step | Run 内逻辑步骤 | 不自动获得新的权限；共享该 Run 的权限上限 |
| ToolInvocation | 一次已确定工具、参数和身份的执行尝试 | 有 action_digest、幂等键、审批/结果状态 |
| Sandbox | 执行代码的临时隔离单元 | 按 Run 惰性分配；不可作为数据的唯一持久层 |
| Workspace | 项目工作数据和每 Run 的工作副本 | 挂载范围和并发写策略必须受控 |
| Artifact | 可下载、预览、分享的任务产物 | 使用 artifact_id 授权，不接受宿主机绝对路径 |
| Capability | Skill/MCP/KB/内置工具等可授权能力 | Skill 是指令与资源包，不等价于自动授权的可执行 Tool |
| Grant | 某主体对某资源的某动作授权 | 主体可为用户/组/项目角色；仍受组织总策略约束 |

## 3. 角色与权限设计

### 3.1 角色

- **员工**：使用授予的 Agent，操作自己的 Session/项目资源，绑定自己的连接。
- **项目管理员**：管理项目成员、文件与共享产物，不天然有权查看每个成员的私人聊天。
- **部门管理员**：维护部门 Agent/能力目录和配额建议，权限不得超过组织允许范围。
- **能力维护者**：提交 Skill/MCP/KB 版本、测试并申请发布；不能自动批准自己的高风险版本。
- **业务审批人**：审批其授权范围的外部写动作，不获得通用平台配置权。
- **组织管理员**：管理组织策略、成员授权和预算；业务数据访问仍需明确权限。
- **平台运维**：管理运行时、部署与指标；默认只能看脱敏元数据，不能解密用户凭据或随意打开会话。
- **安全审计员**：查看受限审计与策略变化，业务正文访问通过独立批准。
- **应急管理员**：限时、可追溯 break-glass，不作为日常登录角色。

底层数据库所有者、主机 root 等仍有基础设施级能力；产品 RBAC 不能消除这种物理权限。需通过岗位分离、密钥托管、运维审计和必要的专属部署控制。

### 3.2 最小权限矩阵

| 动作 | 员工 | 项目管理员 | 部门管理员 | 能力维护者 | 业务审批人 | 平台运维 |
|---|---|---|---|---|---|---|
| 使用已授权 Agent | 是 | 是 | 是 | 按授权 | 按授权 | 默认无业务访问 |
| 读取他人私有 Session | 否 | 否 | 否 | 否 | 仅审批所需最小摘要 | 否 |
| 管理项目成员 | 否 | 本项目 | 被授权项目 | 否 | 否 | 否 |
| 提交个人 Skill | 可提交，默认未发布 | 同员工 | 同员工 | 是 | 否 | 否 |
| 发布部门 Skill | 否 | 按角色 | 审核权限内 | 申请发布 | 否 | 否 |
| 读取原始 Secret | 不通过 API 回显 | 否 | 否 | 否 | 否 | 否 |
| 测试自己的 MCP 连接 | 是，受网关约束 | 是 | 是 | 授权范围 | 否 | 仅诊断元数据 |
| 审批财务/外部写入 | 不能因发起任务自动获得 | 按独立授权 | 按独立授权 | 否 | 授权资源范围 | 否 |
| 停止自己 Run | 是 | 项目任务按授权 | 部门任务按授权 | 自己任务 | 否 | 应急停止权限 |
| 查看容器内部业务文件 | 自己的授权产物 | 不默认授予 | 不默认授予 | 测试数据 | 否 | 经限时支持授权 |
| 启用任意出网/提升运行权限 | 否 | 否 | 否 | 否 | 否 | 安全评审后的部署变更 |

## 4. 功能需求清单

### 4.1 身份、任务与交互

| ID | 级别 | 需求 | 可验收标准 |
|---|---|---|---|
| FR-01 | P0 | 企业登录与退出 | 未登录不能访问业务 API；验证 issuer/audience/state/nonce；退出/离职失效；无默认共享 Token |
| FR-02 | P0 | 组织、部门、项目授权 | 列表、详情、下载、修改均按范围过滤；跨组织访问不返回存在性敏感信息 |
| FR-03 | P0 | 会话归属与隔离 | 自己创建多个 Session；他人不能枚举/读取/删除；未知 ID 不自动创建会话 |
| FR-04 | P1 | Agent 模板与版本 | 只能选已授权、已发布版本；Run 保存版本快照；更新不改变正在执行的任务 |
| FR-05 | P0 | 持久 Run | 创建成功返回 run_id；任务不依附网页连接；API/Worker 重启后状态可解释 |
| FR-06 | P0 | SSE 重连与回放 | 事件有序号；带 Last-Event-ID 重连不丢最终状态、不重复渲染；终态可查询 |
| FR-07 | P0 | 取消与明确恢复 | 取消有后端确认和资源回收；无法确定外部写结果时展示需确认，不自动重跑 |
| FR-08 | P0 | 审批中心 | 绑定工具版本/参数/资源/凭据 scope；过期、越权、重复审批均有稳定结果 |

### 4.2 执行隔离与能力目录

| ID | 级别 | 需求 | 可验收标准 |
|---|---|---|---|
| FR-09 | P0 | 所有本地执行进入隔离单元 | Python/Node/Shell/浏览器/stdio MCP/解析器均不能在控制服务执行用户内容 |
| FR-10 | P0 | 资源与并发配额 | 用户/部门/组织/节点层级限制；CPU/内存/PID/磁盘/时长可验证；超限不会拖垮控制面 |
| FR-11 | P0 | 持久工作区与并发控制 | 一个项目同时最多一个写 Run；每次基于固定版本；产物校验后原子发布 |
| FR-12 | P0 | 依赖安装策略 | 系统依赖仅走镜像构建；临时包仅装 Run 内虚拟环境；不能修改公共 Skill/镜像 |
| FR-13 | P0 | 网络出口与内网访问约束 | 默认拒绝；只允许批准的端点/代理；不能访问管理面、元数据或跨用户运行时 |
| FR-14 | P1 | 统一可授权能力目录 | 支持组织/部门/项目/个人范围；目录可见不等于执行授权；禁用立即阻止新调用 |
| FR-15 | P1 | Skill 发布与固定版本 | 草稿、审核、发布、禁用、回滚；版本 immutable；指令、脚本、依赖、镜像有摘要 |
| FR-16 | P1 | 自定义 Skill 提交 | 上传包经过大小/解压/路径/来源/依赖检查；未批准不执行；不能上传后控制服务自动 import |

### 4.3 MCP 与知识库

| ID | 级别 | 需求 | 可验收标准 |
|---|---|---|---|
| FR-17 | P1 | 远程 MCP 客户端 | 支持选定版本的标准传输；工具发现/调用/错误/超时完整；逐调用校验身份和权限 |
| FR-18 | P1 | stdio MCP 隔离 | 安装/启动发生在专属执行单元；会话不跨用户；崩溃/超时可回收 |
| FR-19 | P0* | 外部写操作一致性 | 开放写工具前必须实现审批、幂等、结果不明与人工核对；不盲目自动重试 |
| FR-20 | P1 | 连接和凭据治理 | 个人/部门连接区别明确；Secret 只可写不可回显；测试连接不能绕过 SSRF 策略 |
| FR-21 | P1 | 知识文档摄取 | 上传→隔离解析→分块→嵌入→可检索，有状态、进度、失败原因和重试 |
| FR-22 | P0* | 检索权限 | 开放 KB 前，召回/重排/引用/下载均受文档 ACL；不能先送模型再过滤 |
| FR-23 | P0* | 知识删除与撤权 | 权限变更阻止新访问，缓存和后续模型上下文同步失效；删除可追踪到索引/对象 |
| FR-24 | P1 | 可信引用与回答质量 | 引用指向有权限的文档版本/位置；证据不足明确说明；不得编造来源 |

`P0*`：对应功能启用的前置条件；首版关闭该能力时可以暂不启用其实现，但不能带缺陷开放。

## 5. 六条端到端用户旅程

### 5.1 财务知识问答，无需代码执行

1. 员工 SSO 登录，后端解析组织与财务知识库授权。
2. 选择“财务制度助手”；后端固定 Agent 版本及允许模型。
3. 创建 Session，提交问题，返回 Run ID 和排队状态。
4. Worker 生成仅包含授权知识能力的 manifest。
5. `knowledge.search` 先校验主体/文档 ACL，再召回；引用读取再次校验。
6. 将最小必要内容发给符合数据策略的模型，生成带来源答案。
7. 记录用量、调用与版本，结束 Run。不为问答本身创建代码容器。
8. 如果员工不具备权限，应返回不能访问/无授权来源，不暴露未授权文档名称与摘要。

### 5.2 销售上传 Excel，生成分析报告

1. 上传使用有大小与用途限制的 upload slot；文件进入隔离区。
2. 服务端确认完整 hash、扫描状态，绑定私人项目。
3. 提交分析任务；获得项目写租约，创建 Run 工作副本。
4. 惰性创建标准分析沙箱，预装审核版本的 pandas/openpyxl 等依赖。
5. Agent 读取受限 Skill，脚本在沙箱运行；输出有界，时间/内存受限。
6. 审核过的临时依赖仅装入该 Run 的 `.venv`；缺失系统依赖返回清楚说明，而不是请求宿主 root。
7. 产物入隔离区、校验、保存 metadata 后发布；前端展示报告与下载按钮。
8. Run 完成后销毁沙箱。清理失败触发运维警报，不把沙箱长期留给下一个用户。

### 5.3 员工接入个人 MCP

1. 从允许的连接器模板创建连接，不直接接受任意 shell command 或内网 URL。
2. 进行 OAuth/凭据绑定，Secret 只进入密钥服务。
3. “测试连接”通过同样的网络策略和权限，不是特权后门。
4. 工具发现保存 schema 摘要与风险；用户选择授权范围。
5. 每次 Run 使用该用户连接；另一个用户不能复用会话 Cookie/token。
6. 发布到部门的是连接器定义或审核模板，而不是偷偷分享个人凭据。
7. 连接撤销后，排队 Run 与后续工具调用均被拒绝；已执行的外部操作不声称可撤销。

### 5.4 部门维护者发布 Skill

1. 创建草稿、填写用途/输入输出/依赖/所需工具/出网/数据分级。
2. 上传不可变包；校验路径、压缩比、可疑 Secret、依赖来源和镜像兼容性。
3. 在合成数据的独立测试 Run 验证，不在管理后端直接执行脚本。
4. 审核者确认风险、适用人群与允许外部写能力。
5. 发布版本并授予部门；新增版本先灰度，不替换正在运行任务的版本。
6. 禁用版本立即阻止新的调用；严重事故可中止正在执行的关联 Run。
7. 回滚只改变新任务引用，不回放旧任务，也不自动撤销已发生业务操作。

### 5.5 Agent 修改业务系统，需要审批

1. Tool Gateway 冻结工具版本、规范化参数、外部资源范围与凭据 scope。
2. 计算 action_digest，持久创建审批与到期时间。
3. UI 展示“将修改哪个系统、哪些记录、预计影响多少条”，原始参数放可展开详情。
4. 被授权审批者批准；后端校验身份、Run 状态、参数未变、凭据/策略仍有效。
5. 执行前持久记录执行意图；向支持幂等的服务发送稳定幂等键。
6. 超时但可能已成功时进入 `outcome_unknown`/`recovery_required`，不再点一下就重新执行。
7. 经外部查询或人工核对确认结果后记录结论；若需要重新操作，创建新调用并按策略重新审批。

### 5.6 管理员集中排障

1. 通过 run_id 搜索脱敏事件、状态、节点、镜像、耗时和失败码。
2. 默认不查看完整提示词、文档或凭据。
3. 必要时向有权人申请限定 Run、限定字段、限定时间的支持访问。
4. 下载脱敏诊断包，或在新沙箱以合成数据/快照 dry-run。
5. 所有支持访问和调试行为自身写审计；禁止直接在执行节点上绕过权限“顺手看所有文件”。

## 6. 页面与交互清单

| 页面 / 路由建议 | 核心内容 | 必须覆盖的状态 |
|---|---|---|
| `/login` | SSO、登录失败、账号停用 | 回调过期、无组织、重复登录、退出 |
| `/agents` | 已授权 Agent、用途、能力与数据提示 | 无可用 Agent、版本停用、无模型权限 |
| `/projects` | 私有/共享项目、成员、存储用量 | 无权限、只读、写租约占用、空间不足 |
| `/sessions/:id` | 对话、上传、运行轨迹、引用、产物 | 排队/执行/待批/保存/失败/取消/待核对 |
| `/runs/:id` | 详细工具调用、资源与版本 | 重连、事件缺口、审批失效、执行结果不明 |
| `/approvals` | 待我审批、我发起、已处理 | 超时、参数改变、权限撤销、重复提交 |
| `/connections` | 个人 MCP、授权状态、测试与撤销 | Token 过期、需重新授权、连接被禁、网络拒绝 |
| `/knowledge` | 可访问知识库、文档、摄取进度、引用 | 解析失败、索引中、ACL 同步中、已删除 |
| `/skills` | 可用 Skill、版本、使用范围 | 草稿/审核/灰度/发布/禁用；员工不见管理按钮 |
| `/admin/agents` | 模板版本、模型、能力、风险策略 | 校验失败、未发布依赖、版本冲突 |
| `/admin/access` | 用户/组/项目/资源授权 | 超过组织策略、同步失败、撤权传播 |
| `/admin/runs` | 排队、失败、节点、限额、应急停止 | 权限受限、不能读正文、需要支持授权 |
| `/admin/usage` | 预算、用量、未知 usage、告警 | 预留与结算分开、不能伪装精确费用 |
| `/admin/audit` | 结构化事件、筛选、导出申请 | 脱敏、留存、导出权限与访问审计 |

### 6.1 业务用户体验要求

- 页面关闭不等于取消；重新打开能回到 Run 当前状态。
- “停止任务”显示停止处理中，直到后端确认。外部写入已发生时显示可能无法撤销。
- 不让员工对看不懂的 Shell 命令进行无意义的逐条批准；低风险沙箱内操作由平台策略预授权，外部高风险动作展示业务影响。
- 文件预览不执行用户 JS；链接跳转不携带平台 Token。
- 明确“为什么不能访问/为什么排队/如何申请能力”，不要只展示 500 或 raw traceback。
- 表单、确认框、消息流支持键盘和焦点恢复；错误、成功不只用颜色表示。
- 功能按钮隐藏只是体验优化，服务器必须独立拒绝未授权请求。

## 7. 非功能要求与起始目标

这些目标用于设计压测，不是现有项目性能结论。G0/G6 结合硬件和业务冻结。

| 维度 | 建议起始目标 | 验证方式 |
|---|---|---|
| API | 常规元数据 API P95 < 500 ms；创建 Run 持久确认 P95 < 1 s | 排除外部模型耗时，在目标并发下测试 |
| 事件 | 事件持久化到前端展示 P95 < 1 s | 包含代理、重连和慢消费者 |
| 沙箱启动 | 已拉取镜像标准 profile P95 < 5 s；冷启动单独记录，先以 < 30 s 为目标 | 按镜像/运行时分别测，不把下载时间藏掉 |
| 取消 | 无远端不可中断调用时，本地执行 P95 5 s 内停止；残留扫描 60 s 内收敛 | 含子孙进程、Node、浏览器 |
| 撤权 | 平台确认撤权后，新 API/工具调用立即按新策略判定；缓存传播目标 <= 5 s | 每次动作仍回源/版本校验，不用 5 s 作为越权宽限 |
| 数据正确性 | 跨用户/跨部门/跨组织越权负例 100% 拒绝 | 全路径测试，不能以总体通过率稀释 |
| 容量 | 10 活跃 Run 的试点负载，执行并发受 profile 资源预算约束 | 代表性文件/浏览器/模型组合 |
| 可用性 | 试点不承诺 HA；生产控制面初始目标 99.9% 月可用需 HA 设施支撑 | 外部模型失败单独计量；不得从平台可用性隐藏本方错误 |
| 恢复 | 生产初始 RPO 15 min、RTO 4 h；最终以成功恢复演练为准 | DB/对象/权限/密钥依赖联合恢复 |
| 安全 | P0 不留未接受风险；不同执行器分别验收 | 见 07，不以 mock 或简单目录测试替代 |
| 可追溯 | 每次外部写具有调用人、审批/策略、意图和结果记录 | 缺少可靠记录时拒绝新的高风险动作 |

### 7.1 留存默认建议，待法务/安全确认

- 会话/任务正文：90 天可配置；团队项目可由公司保留政策覆盖。
- 任务临时工作副本：成功发布后尽快清理；失败副本默认不长期保留，可限时隔离保留排障。
- 正式产物：默认 30 天或项目约定；删除由显式生命周期任务执行。
- 知识文档：跟随数据源和业务政策；删除要传播到索引、引用缓存和派生数据。
- 安全审计：180 天起步，关键财务/合规动作按公司要求延长。
- 密钥：不进入正文/日志/诊断包；Secret 服务独立轮换和审计。
- 备份存在删除滞后窗口，应在隐私政策中明确；恢复时重放删除/撤权记录，避免被删除内容复活。

## 8. 验收业务样本

试点至少准备：

1. 两个部门各 10 个不涉及真实隐私的知识文档，有同名但权限不同的内容。
2. 两个用户的同名文件 `report.xlsx`，结果必须始终隔离。
3. 一个 5–20 MB 的代表性 Excel 与一个异常/损坏文件，验证成功与失败体验。
4. 一个只读 MCP、一个支持幂等的测试写 MCP、一个故意超时的测试服务。
5. 一个只读 Skill、一个需 Python 的 Skill、一个含错误依赖的 Skill、一个不可信指令样本。
6. 掉线、审批后重启、用户离职撤权、配额耗尽等真实场景脚本。
7. 至少 60 条带标准来源的知识问答，覆盖有答案/无答案/越权诱导/文档更新。
8. 每条业务流程有业务验收人；研发自测通过不能替代业务正确性验收。

## 9. 需求冻结与变更

G0 后新增的能力按以下问题评审：是否新增外部系统权限？是否新增执行路径？是否增加数据出境/留存？是否需新镜像/网络端点？是否影响预算和恢复语义？

任何一项为“是”，必须同步更新 03 契约、04 安全、06 任务和 07 测试。不能只在 Skill 提示词里增加一句说明就上线。
