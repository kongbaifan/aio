# P6：企业数据源与可选引擎增强

> 父任务：KB-09、ENG-01～05，共 6 项。全部待实施，默认不在 V1 关键路径。可以在基础契约稳定后独立实验，但不能绕过 P1–P5 的同一授权、执行、预算和放行要求。

## 1. 范围与选型原则

- 首版先保留 LocalHarness 作为默认引擎；新引擎是单独版本化 adapter，不替换平台 Run/权限/账本事实。
- 只接有实际业务收益、明确授权与数据政策的数据源，不把“支持更多连接器”作为必达数量指标。
- 多集群、长期记忆、多人实时编辑、任意第三方市场属于未估算的后续范围，本轮不擅自加进原 110 项或承诺随 V1 交付。
- 一项增强不通过可以保持关闭，不阻止原已验证能力继续运行。

## 2. 任务卡

<a id="kb-09"></a>

### KB-09 — 企业知识源的增量与权限同步

**位置/契约**：`APP/knowledge/connectors/`、source config 与同步 Job；复用现有文档 ACL/版本/摄取链路，不另建弱权限索引。

- [ ] **KB-09.01** 选择一个实际数据源，明确 API/账号 scope、source ID、变更游标、删除事件、权限语义、限流与字段。
- [ ] **KB-09.02** 校验连接器端点和 SecretBinding，数据/ACL 获取都经过出口与预算策略，不给同步器公司全域管理员权限。
- [ ] **KB-09.03** 首次全量同步分批/可恢复，外部 opaque ID 映射 document/source_key，不用标题做唯一键。
- [ ] **KB-09.04** 增量以 source_revision/change token 幂等处理新增/更新/删除/ACL 变化，游标只有可靠发布后推进。
- [ ] **KB-09.05** 处理重复/乱序/缺失事件、分页中断、游标过期与重新全量；一次同步失败不视为源文件已删除。
- [ ] **KB-09.06** ACL 不可获取或超过批准的新鲜度时受影响内容保守不可访问，不无限期使用旧宽权限缓存。
- [ ] **KB-09.07** 源删除/权限撤销优先使访问失效，防旧摄取 Job 发布、旧引用/摘要继续外发。
- [ ] **KB-09.08** 对比源端与平台的可见文档集合，测试跨部门移动、离职、分享撤回、限流/中断和备份恢复。
- [ ] **KB-09.09** 输出该连接器的延迟/新鲜度/失败政策和支持边界，批准后只向少量来源空间灰度。

**验收/证据**：KBTEST-03/04/08/09/10/14、MCPTEST-04 类出口测试；源端权限与平台可见范围可核对。**PR/回滚**：停止同步/禁受影响资源，保留来源和版本记录；不能把停止同步理解为保留旧授权永久可见。

### ENG-01 — 固定 Codex 版本、协议和合规验证清单

**位置/契约**：`DOC/decisions/codex-adapter.md`、固定版本 schema；先评估，不急着改默认引擎。

- [ ] **ENG-01.01** 明确引擎要解决的业务收益和必须支持的模型/认证/工具/事件/取消/恢复能力，与 LocalHarness 基线比较。
- [ ] **ENG-01.02** 锁定候选版本和实际官方说明，导出对应协议 schema，记录实验/不支持生产接口，不能泛化到所有版本。
- [ ] **ENG-01.03** 由公司确认产品条款、企业认证和计费方式，不假设个人账号/订阅允许所有员工共享。
- [ ] **ENG-01.04** 核查模型端点/受控代理/最小凭据模式的兼容性，无法满足数据政策和 Secret 边界就 no-go。
- [ ] **ENG-01.05** 列 RPC/内置工具矩阵：允许、拒绝、需平台审批、仅实验；特别审查原始 shell/process/config/credential 接口。
- [ ] **ENG-01.06** 确定 thread/turn 与 Session/Run 的映射、历史存储和版本升级策略，不以 engine thread ID 代替资源授权。
- [ ] **ENG-01.07** 输出 PoC 验收、风险、投入和停止条件；未决关键项不进入生产适配。

**验收/证据**：兼容/合规/安全 go-no-go 初审，文件带版本与核查日期。**PR/回滚**：文档与实验 flag 默认关闭，不修改 LocalHarness 生产行为。

<a id="eng-02"></a>

### ENG-02 — 隔离 App Server 与私有桥接

**位置/契约**：`APP/runtime/engines/codex.py`、Codex profile 镜像/私有 bridge；整个执行宿主进入获准隔离单元。

- [ ] **ENG-02.01** 构建固定版本镜像，独立 HOME/config/history/workspace/browser 状态，无宿主 home 或管理 Socket 挂载。
- [ ] **ENG-02.02** 由 manager 绑定 Run/generation/profile，bridge 通过私有传输连接，浏览器不直连原始 App Server 端口。
- [ ] **ENG-02.03** 请求/响应 ID、初始化、事件和错误映射到平台 adapter，所有缓冲、输出和长连接有限制。
- [ ] **ENG-02.04** 历史与配置按用户/项目版本化受权保存；容器回收后能否恢复取决于实测，不伪装任意线程透明恢复。
- [ ] **ENG-02.05** 验证最小凭据/模型代理与网络 profile；引擎获取不到合规凭据时失败，不注入公司全局 Key。
- [ ] **ENG-02.06** 退出/崩溃/取消/manager 重启回收所有子进程和句柄，不跨用户复用有状态 App Server。
- [ ] **ENG-02.07** 两用户并发验证 thread、文件、HOME、模型配置和 Cookie 隔离。

**验收/证据**：SBXTEST-01/03/04/08/10/20 的该引擎差量，协议 schema 与镜像一致。**PR/回滚**：关闭 adapter，已有实验 Run 明确终结；不能中途转另一引擎重复执行。

<a id="eng-03"></a>

### ENG-03 — RPC 白名单、工具、审批与费用策略映射

**位置/契约**：Codex adapter policy、bridge dispatcher、ToolGateway 集成；平台安全事实仍由平台决定。

- [ ] **ENG-03.01** 白名单只开放所需方法，未知/新方法默认拒绝，不透传完整 JSON-RPC 给 Web 用户。
- [ ] **ENG-03.02** 对路径/命令/配置/凭据相关接口实行明确拒绝或固定映射，用户不能指定宿主路径、放宽 sandbox 或切换 Secret。
- [ ] **ENG-03.03** 业务 MCP/动态工具（若固定版本支持）映射至同一 Gateway，当前授权、ActionSpec 和 durable Approval 不被引擎本地批准替代。
- [ ] **ENG-03.04** 内置文件/命令可能不经过平台 Gateway，必须靠外层 OS profile 限制并映射审计；不能谎称所有内置调用都二次经业务网关。
- [ ] **ENG-03.05** 保留引擎自带沙箱作为纵深防御；仅在证明外层完整时评审 externalSandbox，不把它当简单的提权选项。
- [ ] **ENG-03.06** 模型调用计费、取消、deadline、数据级别和连接权限都映射平台；无法施加硬边界的功能不开放。
- [ ] **ENG-03.07** 测禁方法/raw process/config 注入、dynamic tool 越权、审批参数替换、预算耗尽和 stale generation。

**验收/证据**：AUTH/RUNTEST/CAPTEST/GOVTEST 相关负例逐一适配；不允许通过换引擎绕过原权限。**PR/回滚**：禁引擎功能/整个 adapter，不把危险 RPC 直接露给用户解决兼容。

<a id="eng-04"></a>

### ENG-04 — 引擎契约、取消、恢复与安全差量

**位置/契约**：`HTEST/integration/engines/codex/`，合成任务和隔离运行时。

- [ ] **ENG-04.01** 使用固定 schema 测初始化、thread/turn、文本/工具/审批/usage/终态/错误映射，兼容性漂移自动失败。
- [ ] **ENG-04.02** 与 LocalHarness 跑同一合成分析任务，比较平台事件/产物/权限语义而非仅最终文字。
- [ ] **ENG-04.03** 在 API/bridge/App Server/节点各处故障，验证没有误报成功或自动重发外部写。
- [ ] **ENG-04.04** 审批重启/失效、取消/进程树回收、断线回放、checkpoint 不兼容明确可解释。
- [ ] **ENG-04.05** 重跑跨用户、Secret、网络、输出/资源、危险 RPC、工具/数据/预算的安全 suite。
- [ ] **ENG-04.06** 记录不支持功能，关闭时 API/UI 一致拒绝；新实验接口不能默认开启。

**验收/证据**：该版本/运行时/工具范围专属报告，不借用 LocalHarness 的通过结果。**PR/回滚**：保持候选关闭，测试失败不影响现有生产引擎。

<a id="eng-05"></a>

### ENG-05 — 引擎选择、费用性能、灰度和回退决定

**位置/契约**：引擎准入决策、feature flag 与试验反馈；非自动替换。

- [ ] **ENG-05.01** 汇总业务收益、正确率、工具可控性、启动/资源/延迟、模型费用和 unknown usage。
- [ ] **ENG-05.02** 审查官方支持成熟度、实验接口依赖、版本升级成本、供应商/数据/认证条款和剩余风险。
- [ ] **ENG-05.03** 明确允许模板/用户/数据/profile 和版本 pin，其他范围不可选择该引擎。
- [ ] **ENG-05.04** 灰度只对新 Run 生效，Session 若换引擎需明确上下文/历史可迁移性，不能默默改变语义。
- [ ] **ENG-05.05** 回退只影响后续新任务，执行中外部动作核对后终结，不通过换引擎重新跑同一副作用。
- [ ] **ENG-05.06** 以 go/no-go/继续实验结论签字，未达生产支持和安全条件就保持实验关闭。

**验收/证据**：业务/安全/平台共同决定，收益不能覆盖权限或凭据缺口。**PR/回滚**：关引擎选择 flag、保留实验历史，默认 LocalHarness 不受影响。

## 3. 官方资料基线与必须重新核查的事实

本轮再次读取的 OpenAI Docs：[Codex App Server](https://developers.openai.com/codex/app-server/)。本规划沿用的另一官方来源：[Codex sandboxing](https://developers.openai.com/codex/sandboxing/)。

当前读取的 App Server 页明确给出实验/生产支持限制，dynamicTools 有实验标记；`thread/shellCommand` 与 `process/spawn` 等可在 Codex 自带 sandbox 外执行。因此：

- 不把 App Server 的存在等同于多租户平台或生产支持承诺。
- 用固定版本 schema 和官方说明决定可用接口，不根据名称猜测行为。
- 外层隔离不能省，平台也不能假设内置方法都经自己的 ToolGateway。
- 真正实施 ENG-01 时再核查具体版本、模型/认证能力与条款，本规划不是未来版本兼容性保证。

## 4. 可选增强的放行顺序

KB-09 可独立于 Codex 工作进行；ENG 必须按 01→02→03→04→05 推进。任何增强先在无生产数据/写权限环境验证，再按 P4 的白名单/配额方法灰度，最后重复受影响的 G6 范围签字。

扩展长期记忆、跨区域、多集群、实时协作或开放市场前，需要新的父任务和估算。不要把未计划工作偷偷塞入本阶段现有任务并沿用原工期。
