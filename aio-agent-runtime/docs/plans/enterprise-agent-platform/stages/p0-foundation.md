# P0：需求、契约、基线与开发环境

> 父任务：FND-01～FND-06。全部待实施。目标不是开放业务功能，而是让后续团队对同一边界、接口、测试样本和禁止项达成一致。

## 1. 进入条件与阶段输出

进入条件：能够读取当前 `aio-agent-runtime`、有业务/安全联系人；拿不到生产账号不妨碍使用合成数据做 P0，但不能伪造已完成企业接入。

退出交付：现状基线报告、首批三条业务旅程、数据分类与信任模型、ADR 决策、接口草案、可重复的假模型/双组织夹具、隔离 Linux 测试条件、来源准入清单。G0 未确认前只允许本地与隔离环境。

冻结的最小决策：组织/部门/项目的关系；SSO 来源；首批模型与数据区域；任意 Skill/外部写是否开放；Linux 运行时与磁盘限额能力；谁批准试点；谁负责故障处置。

## 2. 任务卡

<a id="fnd-01"></a>

### FND-01 — 复现可运行基线与真实测试范围

**改动/交付位置**：`DOC/verification/baseline/` 的摘要；敏感原始输出放受控证据存储。检查当前 `requirements-local.txt`、各 apps 的 requirements、`.github/workflows/ci.yml`、`package.json`，不更改业务行为。

- [ ] **FND-01.01** 记录 git commit、工作区状态、Python/Node/npm/操作系统版本；区分 Windows 开发和 Linux 执行测试。
- [ ] **FND-01.02** 在干净虚拟环境解析依赖，记录实际安装版本/锁文件；不修改共享系统 Python 或复用带生产环境变量的 shell。
- [ ] **FND-01.03** 执行现有 Harness、Sandbox、前端回归和 lint，分别记录退出码、passed/failed/skipped；确认 MCP 测试的可选依赖是否使其被跳过。
- [ ] **FND-01.04** 用 fake 模型跑 single/team、工具拒绝、模型失败、输出截断、UTF-8、SSE；明确哪些仅为 mock 证据。
- [ ] **FND-01.05** 枚举所有本地命令路径和调试入口，将 browser、Node、Shell、模型配置 Shell、MCP Server 与 parser 对应到改造任务。
- [ ] **FND-01.06** 对失败分成现有缺陷、环境问题、规格待确认，不在基线中顺手修大量无关代码；为阻塞路径建立最小复现。
- [ ] **FND-01.07** 产出基线摘要、运行命令、依赖和缺陷清单，由 QA/BE 审核后锁定比较基准。

**验收/证据**：另一人可以在隔离环境复现主要结果；不能引用旧验收报告的通过数替代真实运行。关联后续 OPSTEST-01/04 和执行器旁路矩阵。

**PR/回滚**：报告与测试夹具单独 PR；安装环境可销毁，不替换用户现有配置或删除原 workspace。

### FND-02 — 冻结业务范围、数据级别与威胁模型

**改动/交付位置**：`DOC/decisions/`、PRD 补充；输入为业务样本和组织政策，输出为可判定的允许/禁止矩阵，不只是架构图。

- [ ] **FND-02.01** 确定三条试点旅程及业务验收人：知识问答、文件分析、只读系统查询；记录成功样例与失败时可接受行为。
- [ ] **FND-02.02** 盘点输入/输出/日志/截图的数据级别、保留时长、允许模型和连接器；把 embedding/reranker 同样列入外发对象。
- [ ] **FND-02.03** 定义用户、部门、项目与支持人员权限，确认共享文件不自动公开私人 Session，产物不能洗掉来源限制。
- [ ] **FND-02.04** 列出可信控制面、可信管理代理、不可信代码、第三方 MCP/网页/文件的边界及攻击面；明确普通容器的剩余风险。
- [ ] **FND-02.05** 确认试点禁止项：任意 root、Docker socket、管理网访问、未审 Skill、自助任意 endpoint、高风险业务写等。
- [ ] **FND-02.06** 选择首选 SSO、Linux/运行时、对象存储、Secret 服务与模型端点，记录备选和触发切换的兼容/合规条件。
- [ ] **FND-02.07** 确认并发、文件大小、超时、预算、恢复和可用性目标只是起始值，列出需压测决定的项目。
- [ ] **FND-02.08** 形成 G0 决策单：已确认、待确认、禁止开放、责任人、验证方式；外部条件未满足时限制范围，不默认通过。

**验收/证据**：PM、SEC、ARCH 对数据与开放范围可签字；每条风险有负责人和降级策略。不得将“内网员工”当作免做隔离的依据。

**PR/回滚**：只改变设计；后续变更必须评估身份、执行、凭据和外发影响，并回写任务/测试，不静默放宽策略。

### FND-03 — 固定平台契约与跨组测试夹具

**改动/交付位置**：`DOC/contracts/platform-v2/`、`HTEST/fixtures/platform/`、`WEB` 的 schema 生成约定。契约先行但不生成假装可用的生产端点。

- [ ] **FND-03.01** 定义 Principal、RunContext、资源引用、SecretRef、SandboxBinding 的必填/禁止字段和来源；列出不可由模型设置的字段。
- [ ] **FND-03.02** 固定 Run/Invocation/Approval/Lease 状态、允许迁移、终态含义，区分失败、取消、超时与 outcome_unknown。
- [ ] **FND-03.03** 定义 v2 请求/错误/分页/幂等/revision 约定，明确 403/404 避免泄露资源存在性的使用规则。
- [ ] **FND-03.04** 定义 SSE 事件名、schema_version、seq、Last-Event-ID、snapshot/过期游标、慢消费者断开和重复帧语义。
- [ ] **FND-03.05** 定义 ToolGateway 与 manager/executor 的私有协议，包括 deadline、generation、固定 profile、输出上限与无特权参数。
- [ ] **FND-03.06** 创建 Org-A/B、Alice/Bob、同名文件、同名知识、fake 模型/外部写服务的可重复夹具；不使用真实员工资料或 Token。
- [ ] **FND-03.07** 定义契约验证与类型生成流程：代码实现后生成真实 OpenAPI 并做差异检查；示例 schema 不能长期替代实际路由。
- [ ] **FND-03.08** 各组做一轮“同请求经过四层”的桌面演练，检查字段、错误与授权是否能串联到同一 trace/run。

**验收/证据**：BE/FE/PE/QA 能用相同样例解释提交、审批、执行、保存、取消；覆盖 FR-01～08、FR-34/36 的契约，不声称安全已通过。

**PR/回滚**：契约与夹具一组 PR；破坏性修改先升级 schema 版本并给兼容窗口，不能同时出现两个含义不同的 succeeded。

### FND-04 — 建立可销毁 Linux 执行测试环境

**改动/交付位置**：`INFRA/platform/test-node/`、节点准备说明与受控证据；所有资源标签标明 test。

- [ ] **FND-04.01** 确认独立节点/VM，禁止连接生产数据库、真实业务系统、生产 KMS 和用户网络存储。
- [ ] **FND-04.02** 验证 CPU 架构、内核、cgroup v2、user namespace、虚拟化支持和所选运行时；记录不支持的选项。
- [ ] **FND-04.03** 准备能实际验证字节/inode 限额的临时卷方案；不要拿无限 named volume 充当硬配额证明。
- [ ] **FND-04.04** 建立独立管理账号和运行账号、最小防火墙、镜像仓库访问；测试节点无通用生产凭据。
- [ ] **FND-04.05** 设置测试外层资源上限、节点回收 TTL、日志上限与故障后重建步骤，避免压力样本伤害其他任务。
- [ ] **FND-04.06** 验证 CI runner 的信任边界：不让未经信任的 PR 在拥有管理 Socket/Secret 的自托管节点执行。
- [ ] **FND-04.07** 用无害 smoke workload 验证构建、运行、销毁和证据采集；完整隔离攻击/耗尽测试留给 SBX-13。

**验收/证据**：PE 可以从空节点重建测试环境并销毁；节点不包含业务数据；向 QA 提供环境 fingerprint。

**PR/回滚**：IaC/脚本单独审查；清理仅面向已验证 ID/标签的测试资源，不使用模糊递归删除共享路径。

### FND-05 — 搭建开发骨架与安全模式开关

**改动/交付位置**：当前 `APP/config.py/main.py` 的组装边界；拟新增 `APP/platform_settings.py`、`app/api/v2/`、测试配置、CI 流程。

- [ ] **FND-05.01** 定义 legacy-local、platform-test、platform-production 三种显式模式，默认不暴露新平台路由和旧共享入口。
- [ ] **FND-05.02** 将配置读取与校验分离，生产必需身份、DB、Secret、manager、安全 profile；缺项 fail closed，不在导入时执行旧密钥 Shell。
- [ ] **FND-05.03** 建立模块骨架/依赖注入接口，不在 `main.py` 再放长任务与运行时命令；接口 stub 在测试外明确不可用。
- [ ] **FND-05.04** 约定依赖锁定、Python/Node 版本、lint/typecheck、测试目录与 fake 服务替换点；不无依据一次升级全部归档依赖。
- [ ] **FND-05.05** 扩展根 `.github/workflows/` 的路径过滤与 job，防新 services/web 变更漏测；PR 不带生产 Secret。
- [ ] **FND-05.06** 写明开发启动与退出流程、端口、临时状态清理和安全默认值；Windows 后台进程保持隐藏，Linux 测试与开发机执行权限分开。
- [ ] **FND-05.07** 加入 production 禁匿名/默认 Token/旧路径/宿主 fallback 的静态或启动负例，后续真实后端逐步接入。

**验收/证据**：legacy 回归不受影响，新模式缺配置不能默默启动成开放平台；关联 OPSTEST-01、CAPTEST-09。

**PR/回滚**：骨架/配置/CI 分 PR；关闭新 feature flag 即停止新平台，不更改用户旧 `.env` 或把它提交进仓库。

### FND-06 — 组件来源、许可证、构建链与供应商准入

**改动/交付位置**：`DOC/compliance/component-inventory.md`、依赖 SBOM 和准入决策；不复写/删除归档。

- [ ] **FND-06.01** 区分当前 apps、可复用 services、第三方源码包、仅二进制和来源不明材料，逐项标 owner/source/license。
- [ ] **FND-06.02** 记录将进 V1 镜像的包、浏览器、字体、Office 转换器、Node/Python runtime，建立最小依赖清单。
- [ ] **FND-06.03** 核查提取组件的使用与再分发条件、缺失源码/构建依赖；无法证明可用时排除或替换，不以本地有文件视为授权。
- [ ] **FND-06.04** 对证书、代理材料和历史密钥风险只做受控扫描与索引；发现真实凭据按独立响应流程，不把值粘到报告。
- [ ] **FND-06.05** 确认模型/嵌入/MCP 供应商的企业授权、数据使用/地域、账号与费用方式；不推断某个人订阅允许全公司共享。
- [ ] **FND-06.06** 建立镜像/依赖版本批准、漏洞例外与到期复审机制，输出给 OPS-01 的准入输入。
- [ ] **FND-06.07** 发布可用/受限/禁止/待确认清单；阻塞项有替代方案和负责人。

**验收/证据**：V1 每项外部依赖可以追踪来源与批准范围，未决组件不在生产镜像；关联 OPSTEST-04/12。

**PR/回滚**：清单和配置独立 PR；撤销某组件准入时先禁用对应能力/镜像，不盲删历史任务证据。

## 3. 建议联调和 PR 顺序

- 第一组：FND-01 + FND-02，QA 与业务同时建立样本，不相互等待全部完成。
- 第二组：FND-03 契约评审后，FND-04 测试环境与 FND-05 骨架可并行。
- 第三组：FND-06 准入结论与基线一起冻结；任何必须依赖但未准入的组件从下一阶段计划移除或替代。
- PR-P0-A：基线与夹具；PR-P0-B：业务/安全 ADR；PR-P0-C：契约与模式；PR-P0-D：隔离测试设施与准入。

## 4. 阶段演示脚本

用合成身份说明 Alice 与 Bob 的请求将经历哪些授权；展示 fake Run 的 queued/running/approval/failed 事件；展示 production 缺身份/manager 配置启动被拒；展示同一套基线可复现。此演示不运行任意用户代码，也不宣称平台已安全。
