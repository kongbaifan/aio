# P5：生产硬化、应急演练与正式交接

> 父任务：OPS-06、OPS-07、OPS-08、REL-06，共 4 项。全部待实施。任务数少不表示工作量小：本阶段依赖前面已建成的身份、执行、能力、治理和运维，要求真实设施与组织流程支持服务承诺。

## 1. 进入条件和不应误解的范围

- G5 受限试点已获准并产生代表性使用数据；严重权限/隔离/凭据问题全部关闭。
- 前面“完整治理”已经实现，P5 不从零补预算、审计或备份，而是完成 HA、升级、应急、正式数据切换和交接。
- 真实外部写按连接器/工具逐项审查；P3 的假写测试通过不等于业务系统凭据、scope 和补偿责任已批准。
- 如果设施或人员无法支撑目标可用性，保持受限试点/低一级服务承诺，不在文档中虚报 99.9%。

## 2. 任务卡

<a id="ops-06"></a>

### OPS-06 — 与承诺一致的高可用、故障域和排空

**位置/契约**：`INFRA/platform/production/`、部署/运行手册、HA 测试；HA 不重新定义 Run/授权事实。

- [ ] **OPS-06.01** 根据试点负载确定 API/Worker/manager/PG/对象/代理/执行节点的冗余与故障域，明确仍存在的单点。
- [ ] **OPS-06.02** API 无本地唯一会话/审批/事件状态，多实例共享权威 PG；SSE 重连不依赖 sticky session 保正确。
- [ ] **OPS-06.03** Worker 多副本采用同一数据库租约/fencing，故障接管不重复不可幂等业务操作。
- [ ] **OPS-06.04** manager 的节点代理/调度领导权有明确仲裁，避免两个控制者同时创建/销毁同一 lease；所有操作幂等对账。
- [ ] **OPS-06.05** PG HA/备份/PITR、对象存储持久性与 Secret/KMS 可用性符合目标，Redis 重启不丢业务真相。
- [ ] **OPS-06.06** 执行节点保留余量与备用容量；单节点故障后先核对和取消/重建，不超卖剩余节点或降到弱隔离 profile。
- [ ] **OPS-06.07** 定义 readiness、流量切换、Worker 停领/排空、Run 总 deadline 与部署终止宽限期。
- [ ] **OPS-06.08** 若采用 Kubernetes，验证 service account/NetworkPolicy/runtimeClass/卷配额实际生效；调度器权限不下发到工作 Pod。
- [ ] **OPS-06.09** 逐依赖进行受控单点失效演练：API/Worker/manager/PG/节点/代理，检查身份、事件、unknown 写、清理和账本。
- [ ] **OPS-06.10** 根据实测更新 SLO/RPO/RTO、容量和失效降级说明，提交架构/安全/运维评审。

**验收/证据**：OPSTEST-03/05/06/09；展示故障时间线、有效 lease、资源对账和未被重复的业务动作。不能用“部署了两个 Pod”代替 HA。

**PR/回滚**：新副本先只读/小流量，数据库扩展兼容；回滚前停止新分配并排空。不能回到单机内存审批或由负载均衡随机分配共享用户状态。

<a id="ops-07"></a>

### OPS-07 — 依赖、镜像、证书与凭据的持续升级

**位置/契约**：版本台账、`INFRA/images/`、CI 准入、轮换 Runbook；升级同样受 Gate 约束。

- [ ] **OPS-07.01** 指定每类控制依赖、执行镜像、浏览器、parser、MCP client、数据库扩展的 owner 和版本支持范围。
- [ ] **OPS-07.02** 建周期漏洞/许可证/SBOM 检查、风险分级响应时限、例外到期和不可继续部署规则。
- [ ] **OPS-07.03** 更新使用新不可变镜像/version，测试通过再提升发布指针，不在运行中容器执行系统升级。
- [ ] **OPS-07.04** 浏览器/原生库/parser/runtime 升级重跑相关隔离、文件、网络、进程清理和业务回归，不能只跑单元测试。
- [ ] **OPS-07.05** SSO/JWKS、TLS/mTLS、Secret/KMS、MCP OAuth 轮换演练覆盖双版本过渡和旧客户端关闭。
- [ ] **OPS-07.06** 定义紧急撤回镜像/Skill/模型端点及禁用范围，现有 Run 继续/取消/待核对由风险决定。
- [ ] **OPS-07.07** 保留活跃/回滚所需版本和 schema 支持窗口，清理镜像/对象先查引用，避免删掉恢复依赖。
- [ ] **OPS-07.08** 升级后检查费用、质量、SSE/协议、unknown 用量和审计字段变化，记录差异与已知限制。

**验收/证据**：OPSTEST-04/12、GOVTEST-04，至少一次完整升级和 Secret/证书轮换可复现。**PR/回滚**：回到仍获准版本；被确认不安全版本不得仅因可用而重新启用。

<a id="ops-08"></a>

### OPS-08 — 真实职责分工的事故演练

**位置/契约**：`DOC/runbooks/incidents/`、值班通知/处置记录、隔离演练环境；禁止在生产主动制造逃逸或破坏。

- [ ] **OPS-08.01** 指定事件指挥、安全、平台、业务系统 owner、隐私/法务沟通角色及升级渠道，明确夜间覆盖范围。
- [ ] **OPS-08.02** 演练沙箱异常/疑似污染：禁 scope→隔离网络/节点→撤 capability→保全证据→可信重建→复测。
- [ ] **OPS-08.03** 演练凭据泄漏：定位连接/Run/日志/产物→轮换/撤销→检查外部访问→限制传播，不把证据发公共工具。
- [ ] **OPS-08.04** 演练未知业务写：停重试→查下游幂等/业务状态→审批人工核对/补偿→记录影响，不假称平台回滚已撤销。
- [ ] **OPS-08.05** 演练知识越权：禁 KB/cache→核查 ACL/index/provenance→识别已披露内容→重建受权索引→差量回归。
- [ ] **OPS-08.06** 演练磁盘/队列/预算/审计故障：停止新执行或高风险动作、保留状态空间、精确清理到期资源。
- [ ] **OPS-08.07** 演练备份恢复后的账号/文档撤权和旧 active Run 核对，避免旧事实自动复活。
- [ ] **OPS-08.08** 确认证据保留与支持 grant、PII 脱敏和合法删除要求，运维不能借演练获取无限内容权限。
- [ ] **OPS-08.09** 记录发现/响应/隔离/恢复时间与人为阻塞，更新 Runbook 和任务，复测真正解决的缺口。
- [ ] **OPS-08.10** 给每类事故定义恢复审批人和再开放条件，安全开关不能由“故障结束”自动解除。

**验收/证据**：GOVTEST-05/06/07/08/10、OPSTEST-02/03/06/11。至少每个首版重大事故类别完成桌面演练，关键控制做隔离环境实际验证；二者分别标注。

**PR/回滚**：演练本身有停止条件和资源限制；回滚不销毁审计、外部业务结果或受法定保留的证据。

<a id="rel-06"></a>

### REL-06 — G6 放行、正式数据切换与运营交接

**位置/契约**：release manifest、签字、服务目录、培训/支持流程；放行以实际证据和范围为准。

- [ ] **REL-06.01** 汇总 G0–G5 和 OPS-06/07/08 证据，明确 commit/image/profile/model/Skill/MCP/KB 的批准版本。
- [ ] **REL-06.02** 对每项生产能力列用户/部门、数据级别、网络、外部身份、配额、审批、保留和异常负责人。
- [ ] **REL-06.03** 外部写逐工具核对下游实际幂等/查询/资源权限/业务审批和补偿 owner；无证据保持关闭。
- [ ] **REL-06.04** 若迁移旧数据，按 REL-01/05 预演过的停写→一致备份→增量迁移→verify→白名单流程执行，需明确发布授权。
- [ ] **REL-06.05** 先恢复只读资源与小流量任务，再按范围提升，保留应急停止和版本回滚窗口。
- [ ] **REL-06.06** 定义对用户的可用性、最长任务、数据/费用边界、未知写处理和支持时段，不承诺设施不具备的 SLA。
- [ ] **REL-06.07** 完成值班、预算 owner、Secret 轮换、备份/演练日历和依赖升级交接，权限按职责发放。
- [ ] **REL-06.08** 向员工培训输入限制、引用核对、分享、取消、审批和反馈方式；不让业务人员自己决定宿主提权。
- [ ] **REL-06.09** 记录遗留非关键风险、补救负责人/期限和明确关闭的增强功能；P0 不通过风险登记豁免。
- [ ] **REL-06.10** 产品、业务、安全、运维共同签字，发布后观察窗口的监控/撤回决定有人负责。

**验收/证据**：完整 release manifest 与链接可定位所有证明；正式开放不是“开发认为做完”。**PR/回滚**：照已演练流程停新任务/收缩范围/切回版本，不丢新账本和权限事实，不擅自对外部系统做补偿。

## 3. 生产发布窗口建议

| 时间点 | 工作 | 不能通过时 |
|---|---|---|
| D-7～D-3 | 冻结发布范围/版本、完成 HA/轮换/演练缺口、检查依赖与外部业务权限 | 缩范围或延期，不临时删门禁 |
| D-2 | 复核迁移与恢复点、值班、费用额度、关闭能力、通知与应急开关 | 不安排正式切换 |
| D-1 | 预发布全链路 smoke、安全 P0 回归、版本/配置差异审查 | 修复后重新验证 |
| T0 | 获授权后停写旧入口/迁移 verify/小范围路由切换 | 保持维护/只读，执行回滚 |
| T+1～2h | 登录、Run、SSE、审批、Artifact、预算、清理和外部写核对 | 按指标即时收缩或禁范围 |
| T+1d | 检查夜间任务、孤儿、用量对账、告警响应和用户反馈 | 暂停扩量、修复复测 |
| T+1w | 评估容量、质量、费用、支持投入和遗留项 | 决定保持/扩量/缩减，非自动决策 |

以上为组织安排模板，不是本轮已安排真实发布。

## 4. 持续运营检查

- 每日：unknown 业务写、未结算预留、清理失败、到期授权、异常费用和安全告警。
- 每周：依赖漏洞/例外到期、容量趋势、模型/Skill 质量、失败任务与业务反馈。
- 按政策定期：备份恢复、证书/Secret 轮换、访问权限复核、入库 ACL 同步质量与删除传播。
- 每次新能力/运行时/供应商：增量威胁建模、契约/测试和明确准入，不在 Skill 描述里“声明安全”就发布。

## 5. 完成标准

平台可以在已签字范围内提供服务；任何 root/基础设施高权限仍由公司岗位分离、密钥与运维审计约束，不声称产品 RBAC 能限制主机 root。多用户使用安全、数据正确、故障可解释、事故可处置、费用可核对，是同等重要的验收项。
